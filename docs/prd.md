# Product Requirements Document

## Overview

Rento is an AI-powered apartment hunting platform built for NYC renters. It scrapes listings from Craigslist and StreetEasy, uses Claude AI to analyze apartment photos and score listings against user preferences, and then autonomously negotiates with landlords via email — including drafting opening inquiries, handling counter-offers, and generating ICS calendar invites when a viewing is confirmed. The entire pipeline runs from a single dashboard without the user needing to manually contact landlords.

Built for EmpireHacks 2026.

## Target Users

- **NYC apartment seekers** — people actively looking for apartments who want to save time on repetitive outreach. Their key need is discovering well-matched listings and getting landlord responses without manually writing dozens of emails.
- **Budget-conscious renters** — users who want to negotiate rent down and need a negotiation agent to push on price, deposit, and lease terms on their behalf.
- **Busy professionals** — users who set their preferences once and want the system to work autonomously, notifying them only when a tour is confirmed or negotiation ends.

## Core Features

1. **User onboarding & preferences** — Multi-step onboarding collects housing requirements (bedroom type, neighborhood, budget range, move-in date, commute destination/method), negotiation style (polite/professional/assertive/friendly), negotiable items (rent, deposit, move-in date, etc.), and notification preferences. Stored across four preferences tables. *(Implemented)*

2. **Listing ingestion** — Craigslist and StreetEasy scrapers pull apartment listings and write them to the `apartments` table with host contact info, images, price, and neighborhood. *(Implemented — parsers in `backend/parsers/`)*

3. **Agent 1: Image analysis** — A LangGraph state machine sends apartment photos to Claude Vision (up to 5 images per apartment), extracts style labels (e.g. `"bright"`, `"minimalist"`, `"hardwood-floors"`) and a description, and stores them back on the `Apartment` row. Runs as an APScheduler batch every 2 hours against any apartment with empty `image_labels`. *(Implemented)*

4. **Objective matching / filter** — `POST /api/v1/listings/run-filter` runs a rule-based filter against the user's `ObjectivePreferences` to create `Match` rows for qualifying apartments. Triggered after onboarding. *(Implemented)*

5. **Agent 2: Semantic match scoring** — A LangGraph state machine calls Claude with the user's full profile (style preferences, neighborhood preferences, priority focus, budget) and a list of matched apartments, then returns a 0–10 score and one-sentence reasoning per apartment. Scores are normalized to 0.0–1.0 and stored on the `Match` row. *(Implemented)*

6. **Listings dashboard** — Paginated, filterable, sortable listing view. Supports filtering by negotiation status, match type (perfect/flex), price range, and minimum match score. Sortable by price, match score, or commute time. *(Implemented)*

7. **Agent 3: Autonomous negotiation** — Triggered when the user starts a negotiation on a listing. A LangGraph state machine drafts an opening email (referencing apartment style and proposing 3 visit slots), sends it via SMTP, polls for a host reply, analyzes the reply with Claude (accepted / counter_offer / rejected / no_reply), and loops up to 5 rounds of counter-offers. On acceptance, sends an ICS calendar invite. Writes all outbound/inbound messages to the `messages` table and notifications to the `notifications` table. *(Implemented)*

8. **Negotiation thread view** — Per-listing message thread showing agent/host messages in chronological order. User can also manually send messages. *(Implemented)*

9. **Agent log stream** — Dashboard tab showing real-time log entries from all three agents (search/rank/negotiate phases), with level indicators and filtering by phase and log level. *(Implemented)*

10. **Tours tracking** — Derived from Agent 3 logs; shows apartments where a tour was mentioned in negotiation context. No dedicated Tour table yet — uses heuristic keyword matching on agent3_logs. *(Partial — flagged as TODO in code)*

11. **Notifications** — In-app notifications generated by Agent 3 on negotiation outcome (visit confirmed or outreach ended). Paginated feed with mark-read and mark-all-read. *(Implemented)*

## Non-Goals

- Rento does not manage lease documents or payments.
- Rento does not provide legal advice or tenant rights guidance.
- Rento does not support cities outside NYC (scraper logic and neighborhood data are NYC-specific).
- Rento does not support human-in-the-loop review before each negotiation email is sent; Agent 3 operates fully autonomously once triggered.
- There is no mobile app; the interface is a web SPA only.

## Success Metrics

- Time from signup to first confirmed viewing (lower is better)
- Match score accuracy: user like/dislike rate on surfaced listings
- Negotiation success rate: ratio of negotiations ending in `completed` vs `not_started` rollback
- Agent 3 round efficiency: average rounds needed to reach acceptance
